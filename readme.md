# TeamFinder

TeamFinder — веб-приложение для поиска участников в команды pet-проектов.
Сервис позволяет пользователям создавать проекты, присоединяться к чужим проектам, просматривать профили участников и указывать необходимые навыки для проектов.

В проекте реализован вариант 3: необходимые навыки проектов и фильтрация проектов по навыкам.

## Возможности проекта

* регистрация и авторизация пользователей по email;
* просмотр списка актуальных проектов;
* просмотр публичных профилей пользователей;
* создание, редактирование и завершение своих проектов;
* присоединение к чужим проектам;
* редактирование профиля пользователя;
* смена пароля;
* автоматическая генерация аватара пользователя с первой буквой имени;
* отображение участников проекта;
* добавление и удаление необходимых навыков проекта без перезагрузки страницы;
* автодополнение при добавлении навыка;
* фильтрация проектов по необходимым навыкам;
* админ-панель Django для управления пользователями, проектами и навыками.

## Подготовка переменных окружения

В корне проекта есть файл `.env_example`.
Перед запуском нужно создать файл `.env`:

```bash
cp .env_example .env
```

Пример содержимого `.env`:

```env
DJANGO_SECRET_KEY=change_for_safety
DJANGO_DEBUG=True
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,0.0.0.0,testserver
DJANGO_CSRF_TRUSTED_ORIGINS=http://localhost:8000,http://127.0.0.1:8000

POSTGRES_DB=team_finder
POSTGRES_USER=team_finder
POSTGRES_PASSWORD=team_finder
POSTGRES_HOST=db
POSTGRES_PORT=5432
```

Описание переменных:

| Переменная                    | Назначение                     |
| ----------------------------- | ------------------------------ |
| `DJANGO_SECRET_KEY`           | секретный ключ Django          |
| `DJANGO_DEBUG`                | режим отладки                  |
| `DJANGO_ALLOWED_HOSTS`        | разрешённые хосты              |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | доверенные источники для CSRF  |
| `POSTGRES_DB`                 | имя базы данных PostgreSQL     |
| `POSTGRES_USER`               | пользователь PostgreSQL        |
| `POSTGRES_PASSWORD`           | пароль пользователя PostgreSQL |
| `POSTGRES_HOST`               | хост PostgreSQL                |
| `POSTGRES_PORT`               | порт PostgreSQL                |

Файл `.env` нужен только для локального запуска и не добавляется в репозиторий.

## Запуск проекта через Docker Compose

Из корня проекта выполните команду:

```bash
docker compose up --build
```

После запуска приложение будет доступно по адресу:

```text
http://localhost:8000
```

При старте контейнера автоматически выполняются миграции, создаются тестовые данные и запускается Django-сервер.

Данные PostgreSQL и загруженные media-файлы сохраняются в Docker volumes.

## Остановка проекта

```bash
docker compose down
```

## Полный сброс базы данных и media-файлов

```bash
docker compose down -v
docker compose up --build
```

## Проверка проекта

Проверка Django внутри Docker:

```bash
docker compose exec web python manage.py check
docker compose exec web python manage.py test
```

Локальная проверка без Docker может быть выполнена через SQLite:

```bash
USE_SQLITE=True python manage.py check
USE_SQLITE=True python manage.py test
```

## Особенности реализации

* Реализован вариант 3: необходимые навыки проектов и фильтрация проектов по навыкам.
* В проект добавлены Django-приложения `users`, `projects` и `core`.
* Приложение `users` отвечает за регистрацию, авторизацию, профили пользователей, редактирование профиля и смену пароля.
* Приложение `projects` отвечает за проекты, участников проектов, статусы проектов и необходимые навыки.
* Приложение `core` используется для общих констант, валидаторов, миксинов и вспомогательных функций.
* Добавлены модели `User`, `Project` и `Skill`.
* Для пользователей используется кастомная модель `User` с авторизацией по email.
* Для проектов используется модель `Project`, связанная с автором проекта, участниками и необходимыми навыками.
* Для необходимых навыков используется модель `Skill`.
* Добавлен запуск всего проекта через `Dockerfile` и `docker-compose.yml`, чтобы приложение работало вместе с PostgreSQL.
* При запуске контейнера автоматически выполняются миграции и создаются тестовые данные для проверки проекта.
* Аватар пользователя генерируется автоматически: первая буква имени отображается на однотонном фоне.
* Проекты на главной странице сортируются по дате создания от новых к старым.
* Добавление и удаление навыков проекта выполняется без перезагрузки страницы.
* Автодополнение навыков помогает выбрать уже существующий навык или добавить новый.
* Фильтрация проектов по навыкам работает через GET-параметр `skill`.
* Загруженные пользователями media-файлы не добавляются в репозиторий и хранятся отдельно.
